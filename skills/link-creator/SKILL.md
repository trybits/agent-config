# 创建目录联接（Junction）

在 Windows 上把一个目录挂到另一个位置，使目标目录通过链接路径也可访问，内容实时共享、不复制文件。

**适用环境**：本技能**仅适用 Windows**（目录联接依赖 NTFS 的 junction 机制）。macOS / Linux 没有 junction，需改用符号链接（`ln -s`），不在本技能范围。动手前先做「环境检查」确认本机系统匹配。

本技能**只处理目录**，统一使用 Junction（目录联接）——创建**无需管理员权限或开发者模式**，Windows 默认环境即可直接使用。

## 环境检查

动手前先确认本机系统是 Windows，避免在不适配的系统上跑命令：

```
if ($env:OS -eq 'Windows_NT') { 'Windows ✓' } else { '非 Windows' }
```

- 系统为 **Windows** → 继续下一步。
- 系统为 **macOS / Linux** → 告知用户本技能仅适用 Windows（junction 依赖 NTFS 机制），停止；若用户仍想链接目录，说明需改用符号链接 `ln -s`，不在本技能范围。

## 前提检查

创建前逐项检查：

1. **目标路径必须存在且是目录**：本技能只处理目录，目标是文件则告知用户不支持；不存在则终止并询问是否先创建目标目录。
2. **链接路径已存在同名项**：先与用户确认。要替换则先安全删除旧链接（见「撤销链接」），再创建新链接。
3. **链接路径的父目录不存在**：征得用户同意后创建父目录。

## 创建

PowerShell 命令：

```
New-Item -ItemType Junction -Path "<链接路径>" -Target "<目标路径>"
```

cmd 等价写法：`cmd /c mklink /J "<链接路径>" "<目标路径>"`

> 容易混淆的一点：`mklink /J` 与 `New-Item -ItemType Junction` 创建的是**同一种东西**（NTFS 目录联接），产物完全一致，只是 cmd 与 PowerShell 两种写法。

若创建失败，常见原因是目标为文件、位于网络路径或非 NTFS 卷，将错误信息如实告知用户。

## 验证

创建后**必须验证可用**，验证失败要报错并停止，不要假装成功：

1. 确认链接类型与目标：`Get-Item "<链接路径>" | Select-Object Name, LinkType, Target`
   `LinkType` 应为 `Junction`，`Target` 指向目标路径。
2. 通过链接访问目标内容：`Get-ChildItem "<链接路径>"`，确认能看到目标的文件。
3. 通过链接读取目标内的关键文件，确认内容可用（若挂载的是技能目录，可额外确认 `<链接路径>/SKILL.md` 或 `skill.md` 可读、与目标一致）。

## 批量创建

用户可能给出多组链接（同一共享目录挂到多个项目、或多个目录各挂一处）。对每组依次执行「前提检查 → 创建 → 验证」，逐条报告。

常见场景举例（不限于技能）：
- 把共享资源/技能目录挂到项目内：`<项目路径>/<挂载点>` ← `<共享目录>`
- 把常用数据/文档目录挂到固定工作位置：`<工作位置>/<别名>` ← `<数据目录>`
- 挂载技能到项目：`<项目>/.claude/skills/<技能名>` ← `<技能源目录>`

## 撤销链接

删除链接**只移除联接条目本身，绝不删除目标目录的内容**。这与全局"删除文件走回收站"规则并不冲突——那条规则针对真实文件内容，这里 `Remove-Item` 仅移除联接条目，不触碰任何文件；若用户要连目标内容一起删，才需对目标本体走回收站。

- 首选安全命令：`Remove-Item "<链接路径>"`（**不加 -Recurse**），只移除联接条目，目标内容完好。Windows PowerShell 5.1 与 PowerShell 7 实测均正常（10/10 次成功，含 junction 套真实目录、目标在仓库外等场景）。
- 注意：5.1 在个别路径上存在**偶发**崩溃（实测对 `.claude` 相关路径偶发 segfault / NullReferenceException，非 junction 特有、无法稳定复现）。若 `Remove-Item` 报异常，改用 `pwsh` 执行或直接走下面兜底。
- 兜底方案：`.NET` 非递归删除 `[System.IO.Directory]::Delete("<链接路径>", $false)`，底层调用 Win32 `RemoveDirectory`，对 junction 只删联接条目、不触碰目标，实测可靠。
- **绝对禁止**对链接使用 `Remove-Item -Recurse` 和 `rmdir /s`：会沿联接递归删除**目标目录的真实内容**，属高风险误删。
- 若用户还想连目标原始内容一起删除，则对**目标目录本体**走回收站（遵循全局文件删除规则），绝不能经由联接递归删除。
- 删除前先向用户确认。

## git 提示

- 链接位于 git 仓库内时，目标在仓库外 → **链接只在本机有效**，其他机器 clone 后失效。
- 若仓库 `core.symlinks=false`（Windows 上常见）：`git add .` 会穿入 Junction，把目标内容作为普通文件纳入版本库。
- 担心穿入前**先查是否已被忽略**：`git check-ignore -v "<链接路径>"`（在仓库根目录执行）。已命中忽略规则（如仓库已忽略 `.claude` 目录）→ 如实告知用户已忽略、无穿入风险，**不要再建议**加 `.gitignore`；未被忽略且用户不想把共享内容提交进仓库时，才建议把链接路径加入 `.gitignore`（先征得用户同意）。

## 报告格式

创建/批量/撤销完成后向用户报告，每条链接一行：

```
<链接路径> → <目标路径>（Junction），验证通过 ✓ / 失败：<原因>
```
