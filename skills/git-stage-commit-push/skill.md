# 暂存提交推送流程

## 步骤

1. **暂存**：`git add .`
2. **检查**：`git diff --cached --stat`，无改动则终止
3. **编写提交描述**：按下方规范编写，展示给用户确认
4. **提交并推送**：用户确认后执行提交命令。

   消息写法：
   - 单行：`git commit -m "type(scope): 摘要"`
   - 多行（标题 + 正文）：标题一个 `-m`，正文每个段落独立一个 `-m`
     ```
     git commit -m "type(scope): 标题" -m "1. xxx。" -m "2. xxx。" -m "3. xxx。"
     ```

   **注意**：不要在一个 `-m` 里手动加换行符，这会导致 PowerShell 环境下正文合并为一行。每个段落用独立的 `-m` 排列即可。

   推送：`git push`，若未设 upstream 则 `git push -u origin <当前分支>`

## 提交描述规范

提交描述应从**产品交付视角**出发，用面向产品经理的语言描述本次交付了什么产品能力、实现了什么业务需求，而非罗列技术实现细节。

```
# 单点改动 —— subject 一行即可
type(产品模块): 交付了什么产品能力 / 实现了什么业务需求

# 多项改动 —— subject 写概括性标题，body 逐条编号
type(产品模块): 本轮交付的核心产品能力
1. 描述新增/优化了什么功能特性，对应什么业务场景。
2. 同上。
...
```

- **type**：`feat` 新功能 | `fix` 修复 | `refactor` 重构 | `perf` 性能优化 | `style` 样式调整 | `docs` 文档 | `test` 测试 | `build` 构建 | `ci` CI 配置 | `chore` 杂项 | `revert` 回退 | `data` 数据更新
- **scope**：改动的产品模块名
- **subject**：用产品交付语言描述「本次交付了什么能力」
- **body**（多项时）：空一行后 `1. xxx。 2. xxx。` 逐条列出，每条说明交付了什么产品特性或解决了什么业务问题
- **语言**：scope、subject、body 行文以中文为主。描述应让产品经理一看就明白这个提交对应哪个需求、带来了什么产品变化

## 边界处理

| 场景 | 处理 |
|------|------|
| 无变更 | 告知用户，终止 |
| 用户拒改 | 询问修改意见，重写后再次确认 |
| 推送失败 | 报错信息，让用户决定 |
