# 页面规则内容编写约定（README 模板）

> 复制到目标项目：`src/config/page-rules/README.md`。内容可照抄，路径按项目实际情况调整。

## 定位

页面右下角的「需求文档」悬浮球展示当前页面（按路由匹配）的业务规则与逻辑说明，供真实业务开发对照。内容为**只读展示**，由产品同学 + Claude 在代码中维护。

**以代码为准**：规则内容必须如实反映页面实际行为（包括占位/未实现功能），页面代码改动时必须同步更新对应 `.md`。错误或过时的规则比没有规则更危险。

**交互**：
- 悬浮球可拖到页面任意位置（位置与面板尺寸持久化记忆）
- 点击悬浮球展开/收起需求文档面板；面板根据悬浮球位置智能翻转（球在左半边 → 面板在球右侧，反之在左侧），支持拖拽右下角调整宽高
- **当前页面未配置规则时不显示悬浮球**

## 新增一条页面规则（四步）

1. 在 `content/` 下新建 `.md` 文件（UTF-8，中文，**从 H2 开始写，不用 H1**——面板头部已显示标题）
2. 在对应领域注册文件（如 `management-center.ts`）中 `import xxx from './content/xxx.md?raw'` 并追加条目：
   ```ts
   { title: '页面名 · 页面规则', match: '/path/to/page', content: xxx }
   ```
3. 选择匹配方式：
   - **`match`（精确）**：路径无动态参数，与 `location.pathname` 全等匹配，优先
   - **`matchPrefix`（前缀）**：路径含 `:id` 等动态段，多个动态页可共用一条规则；取最长前缀命中
4. `pnpm dev` 验证：进入该页面，悬浮球为主色可点击，展开后内容正确渲染

## 路径匹配规则

- 匹配的是 `location.pathname` 实际值（如场景管理恒为 `/management-center/scene-manage`，不是 `:tab` 形式）
- 精确匹配优先于前缀匹配；前缀匹配取最长
- 未命中任何规则的页面：不显示悬浮球

## 格式约定

- 优先 GFM 语法（表格、任务列表），react-markdown + remark-gfm 已配置
- 不引用图片资源（保持纯文本便于 diff 审查）
- 正文控制在 1–2 屏内（`?raw` 导入会内联进 JS 产物）

## 注意事项

- 内容面向内部开发对照，勿写入机密/客户信息
- **未实现功能必须如实标注**（如「占位弹窗」「无点击逻辑」），避免开发误以为已实现
- 建议用「未实现 / 占位清单」表格集中列出当前页面的占位功能
- 页面代码与规则内容冲突时，以代码为准并修正 `.md`
